## 简介
dsh-novel 是一个运行在 DeepSeek Harness（DSH）中的小说插件：把 legado 书源导入 DSH，做聚合搜索、加入书架、连续翻页阅读；同时暴露 `dshnovel_search`、`dshnovel_read` 等 AI 助手工具，让“找书 + 读第 N 章”可以在对话里完成。它不内置任何书源，数据默认留在本机 `~/.dsh/novel/`。

本指南按用户角色拆分步骤，所有界面元素和调用方式均对应仓库中真实实现。

## 三类用户的快速步骤

### DSH 普通用户
1. **安装插件**  
   在目标 profile 中执行：  
   `dsh plugin --profile <profile> add @xrn1997/dsh-novel`  
   重启宿主后，左侧栏会出现「小说」图标。

2. **打开面板**  
   点击左侧栏「小说」图标，中央面板打开书架、书城与书源管理 tab。

3. **首次导入书源**  
   - 进入「书源管理」tab。  
   - 选择 legacy JSON 文件（可多选），或粘贴 legado 书源 JSON。  
   - 导入在服务端后台执行，关闭页面不会中断。

4. **批量验证书源**  
   - 新导入的书源默认是「未验证」。  
   - 顶部「待办收件箱」会把坏源或未验证源置顶成任务卡。  
   - 点击「一键验证」「批量重验」，服务端并发限流执行。

5. **聚合搜索**  
   - 在书架 tab 顶部输入书名/作者关键词。  
   - 服务端对已启用的文本书源并行搜索，结果按（书名，作者）归并，每本书展示多家源行。

6. **加入书架**  
   - 搜索结果中点某条源行的详情页地址，或点击「都加架」逐条入架。  
   - 书架条目记录封面、阅读进度与来源书源名。

7. **阅读器连续翻页**  
   - 点封面进入阅读器。  
   - 支持连续滚动；滚动到底自动预取下一章；支持目录抽屉跳章。  
   - 字号、行距、栏宽、纸张色可调，深浅主题自适应。

8. **导入本地书**  
   - 书架末位有「导入本地书籍」卡片，支持 TXT 与 EPUB。  
   - EPUB 封面缺失时，导入说明会持久化提示，可在阅读器内重看。

## AI 助手工具用法

### 推荐调用顺序
1. 调用 `dshnovel_search`，传入关键词。  
2. 从返回结果的某条源的 `url` 取出 `bookKey`，并记住对应的 `sourceId`。  
3. 调用 `dshnovel_toc` 查看目录，确定第 N 章的 `chapterIndex`。  
4. 调用 `dshnovel_read`，传入 `sourceId`、`bookKey`、`chapterIndex`。

```mermaid
sequenceDiagram
    participant Agent as "AI 助手"
    participant Tools as "tools.ts"
    participant Service as "ReadingService"

    Agent->>Tools: "dshnovel_search(keyword)"
    Tools->>Service: "search(keyword)"
    Service-->>Tools: "books / failed / searched / answered / filtered"
    Agent->>Tools: "dshnovel_toc(sourceId, bookKey)"
    Tools->>Service: "getToc(sourceId, bookKey)"
    Service-->>Tools: "chapters[]"
    Agent->>Tools: "dshnovel_read(sourceId, bookKey, chapterIndex)"
    Tools->>Service: "getChapter(sourceId, bookKey, chapterIndex)"
    Service-->>Tools: "纯文本正文"
```

### 返回值要点
- `dshnovel_search` 返回的是按书归并后的视图；`failed` 列出未答话的源；`searched`、`answered`、`filtered` 区分“没人答话”和“答话但都不相关”。  
- `dshnovel_read` 返回纯文本正文，图文书插图投影为 `[图片：替代文字]` 占位。  
- 工具参数缺失会直接抛错，避免弱模型猜参写出无效 `bookKey`。

### 常用键值
| 键 | 默认行为 | 用途 |
|---|---|---|
| `dataDir` | `$DSH_HOME/novel/` | 数据根目录，含 `sources.json`、`shelf.json`、缓存与本地书 |
| `searchTimeoutMs` | `15000` | 单源搜索超时毫秒 |
| `searchParallel` | `5` | 搜索并发书源数 |
| `jsTimeoutMs` | `15000` | js 沙箱预算，阅读/搜索/探针/登录共用 |
| `cacheMaxBytes` | `200MB` | 目录/正文缓存上限，LRU 淘汰 |
| `exportDelayMs` | `300` | 范围导出章节间串行间隔 |
| `localImportMaxBytes` | `50MB` | 本地 TXT/EPUB 导入大小上限 |
| `proxyUrl` | 启动时自动探测 | 出站代理；`direct` 强制直连，或显式 http(s) 地址 |

数值项按整数校验；`proxyUrl` 只接受 `direct`、空串或 http(s) 地址，裸 `host:port` 会补 `http://`。非法值在插件加载期报错，配置页保存时同样拒绝。

## 性能与容量特性
- 聚合搜索默认并发 5，可通过 `searchParallel` 调整。  
- 搜索命中截断有内存上限，避免无界增长。  
- 目录/正文缓存默认 200MB，超过上限 LRU 淘汰。  
- 本地书导入默认 50MB；EPUB 解析分两遍，逐份文档转换，不把整本 DOM 常驻内存。  
- 范围导出串行限速，默认章节间隔 300ms。

## 常见问题排查

### 无法连接书源
**现象**  
搜索结果为空，或书源探针失败。

**排查步骤**
1. 检查书源是否启用：`enabled` 缺省归一为 true，老数据会迁移补齐。  
2. 在「书源管理」中对单源执行探针，查看失败码与消息。  
3. 确认书源类型是文本类；漫画/短剧不参与聚合搜索。  
4. 如果是站点对直连外网出口 302 跳转，检查代理是否生效。

### 代理未生效
**原因**  
插件使用 Node 的 fetch，undici 不读系统代理；浏览器能开不代表插件也能访问。

**取值优先级**
1. `config.proxyUrl`  
2. 环境变量 `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`  
3. Windows 系统代理（HKCU Internet Settings）  
4. 直连

**修复建议**
- 显式设置 `proxyUrl`，如 `http://127.0.0.1:7897`。  
- 想强制不走代理，设为 `direct`。  
- 裸 `host:port` 会自动补 `http://`；非法地址会被拒绝。  
- 日志中的代理地址会脱敏，避免泄露密码。

### EPUB 封面缺失
**现象**  
导入 EPUB 后书架没有封面，或阅读器找不到封面。

**原因**
- 封面资源不存在是正常情况，不是导入失败。  
- 如果封面资源损坏、超预算或被加密，导入会失败并点名具体资源。  
- EPUB 解析只读取 spine 主序列与可达补充文档；未使用的 manifest 条目不受影响。

**处理建议**
- 查看书架导入说明或 `GET /local/warnings`，确认是否有损告警。  
- 检查 EPUB 包中封面资源是否存在且可读。  
- 若是内联 SVG 封面，只有当它是该文档唯一内容时才可能按图片页处理。

### 搜索结果为空
**可能原因**
- 没有启用可用的文本书源。  
- 关键词太严格，命中都被判为不相关。  
- 书源规则未命中书名/作者/分类。  
- 书源失败但未响应，计入 `failed`。  
- 结果超过上限被截断，但仍有总数信息。

**排查建议**
1. 先跑「一键验证」，排除坏源。  
2. 缩小关键词范围，例如只输书名关键字。  
3. 查看 `dshnovel_search` 返回的 `searched`、`answered`、`filtered`、`failed`。  
4. 对单个源试跑，确认其搜索面是否可达。  
5. 如果是分页站点，注意当前实现主要命中首页结果，未必覆盖全站。

## 结论
dsh-novel 的核心价值是把 legacy 书源搬进 DSH，并提供统一的搜索、书架、阅读与 AI 工具链路。普通用户通过左侧栏「小说」面板即可完成导入、搜索、加架与阅读；插件开发者应复用 `ReadingService`，不要维护第二套业务逻辑；legado 书源作者需确保文本面规则有效，并善用探针与批量验证。常见问题多数落在书源类型、代理配置与 EPUB 结构上，按本文排查路径通常能快速定位。
