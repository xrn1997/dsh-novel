## 引言
dsh-novel 是 DSH（DeepSeek Shell）中的一个“小说”插件，同时运行在 Node 半和浏览器半：Node 端提供 HTTP API、书源抓取、缓存、书架、后台任务；浏览器端提供全局面板、搜索/发现/阅读器 UI。文档目标是给出系统边界、组件关系、数据流、门面模式、Wire-first 契约、活配置以及扩展方式，帮助读者快速定位新增路由、面板、书源语法或导出格式的接入位置。

## 核心组件
- **组合根 `src/index.ts`**：Cordis 插件 `apply`，装配 WebServer 路由、ToolsRuntime、JobsRuntime、ReadingService，并安装双态日志 Sink、未处理拒绝守卫、热更监听。通过窄接口镜像宿主能力，避免强依赖未安装的 dsh-host-webserver。
- **门面 `ReadingService`**：HTTP/AI 工具/UI 三方共享的业务入口。对外只暴露动词方法；内部持有 SourceRegistry、Shelf、PageCache、Fetcher、SearchJobs、ExploreJobs、LocalBooks 等部件。
- **HTTP 分发器 `dispatch.ts`**：`/novel-api` 前缀路由的单一入口，按 segment 分派到 ReadingService 方法，返回 JSON 信封或 SSE 流。
- **Wire 契约 `shared/wire.ts`**：Node 半与浏览器半之间的唯一真相——API 值形状、路由段名、枚举、状态、错误信封。构建时会被浏览器端 inline，禁止运行时 Node 依赖。
- **Fetcher**：守门网络出口，负责 UA、代理、超时、非 2xx 分类为 FetchError、Cookie/Headers 透传。
- **日志 Sink**：模块级 `log`，默认直写 console；运行时由组合根替换为 console + ctx.logger 复合 sink，卸载后复位。
- **浏览器面板入口 `client/index.tsx`**：注册全局面板图标、中央面板、常驻状态层，并通过 CopyProvider 注入翻译。

## 详细组件分析

### 组合根 `src/index.ts`
- 定义窄接口 `WebServerLike` / `ToolsRuntimeLike` / `JobsRuntimeLike`，仅镜像宿主用到的成员，避免对未安装的 dsh-host-webserver 产生编译期依赖。
- `inject = ['webServer','tools','jobs']` 声明 Cordis 前置能力；重复 apply 通过 `applied` 标志防止重复注册 `/novel-api`。
- 安装双态日志 Sink：console 保本机可见性，ctx.logger 进 ring buffer；effect dispose 时复位为 console。
- 监听 `loader/volatile-update`，打印热更路径并在 `proxyUrl` 变化时重新计算代理。
- 使用 `afterReady` 封装 ready 失败吞掉、dispose 复位 applied、取消检测，确保路由/工具注册顺序稳定。
- 安装 unhandledRejection 守卫，保护 Node 进程不被脚本异步 rejection 杀死。
- 通过 `jobs.attachController('dsh-novel')` 让本地 job controller 对全局 owner 生效。

### HTTP 分发器 `src/api/dispatch.ts`
- `createApiHandler(service)` 返回 `(req,res)` 处理器：校验受信来源、校验 `/novel-api` 前缀、解析 segment，再交给 `route`。
- 健康检查直接返回 `{name:'dsh-novel',apiVersion:1}`。
- 书源面：列出公开源、导入任务、任务状态、批量探测、逐源 probe/auth、启用/批量启用/删除。
- 阅读面：搜索计划、提交搜索任务、取消、SSE 进度流；后续继续覆盖探索、导出、本地书等路由。
- 所有成功响应经 `writeOk`，失败经 `writeError`；body 形状错误先转成 ApiError。
- SSE 通用机械 `openJobStream`：写头、周期性推帧、终态关流、断连退订。

## 错误处理与日志

### 两态日志 Sink
- 默认 sink 是 console，离线/测试可用。
- 运行时由组合根 `setLogSink` 替换为复合 sink：info 走 console.log + ctx.logger，warn/error 走 console.warn/error + ctx.logger。
- 卸载 effect 将 sink 复位为 console，避免指向已卸载实例。
- 引擎层不直接依赖 services/log，unhandledRejection 守卫通过注入 warn 回调进入日志缝。

### 统一响应信封
- 成功：`{ ok: true, value }`，由 `writeOk` 统一输出。
- 失败：`{ ok: false, error: { code, message, segment? } }`，由 `writeError` 输出。
- `errorStatusOf` 区分两类错误：
  1. `ApiError`：自带 status/code/segment，直通。
  2. domain/引擎错误：经 `classify` 映射到 ErrorCategory，查表得到 status/code，引擎错误附带 facet/segmentIndex/raw。
- body 读取限制在 `readCappedBody` / `readJsonBody`，超限 413，非法 JSON 400。

```mermaid
flowchart TD
  Throw["抛出错误"] --> IsApiError{"instanceof ApiError?"}
  IsApiError -->|是| UseApiError["使用 e.status/e.code/e.segment"]
  IsApiError -->|否| Classify["classify(e) → ErrorCategory"]
  Classify --> MapTable["STATUS_OF 表映射"]
  UseApiError --> WriteJson["writeJson(status,{ok:false,error})"]
  MapTable --> WriteJson
```

## 性能考量
- 聚合搜索并发 `DEFAULT_SEARCH_PARALLEL` 与 JS 沙箱预算 `DEFAULT_JS_BUDGET_MS` 在 ReadingService 与 fetcher 默认处统一，避免散落字面量导致批循环挂死或目录脚本超时。
- Fetcher 对代理 dispatcher 做 URL 级缓存与 dispose 清理，避免连接池泄漏；代理地址非法转为 FetchError，并脱敏日志。
- SSE 流用 `openJobStream` 统一收尾，断连即退订，避免积压与僵尸连接。
- 本地导入与信封体共用 `readCappedBody`，字节上限唯一主人，避免重复计数逻辑。

[本节为一般性指导，无需具体文件分析]

## 故障排查
- 重复启用导致路由崩溃：检查 `applied` 标志与 Cordis unload/load 流程，确认 dispose 已复位。
- 本机日志不可见：确认组合根已设置 log sink；注意 host logger 缺省级别可能过滤 warn/debug，console 腿是保底。
- 外部站点 403/重置：检查代理配置与 `proxyUrl` 热更；Fetcher 会记录脱敏后的代理地址。
- 请求体过大：确认上传文件大小不超过 `readCappedBody` 上限；本地导入与 JSON 信封共享该限制。
- SSE 连接不关闭：检查 `openJobStream` 是否收到终态、前端是否主动断开。

## 结论
dsh-novel 以 ReadingService 作为唯一业务门面，以 shared/wire.ts 作为跨半契约，以组合根完成宿主窄接口装配与生命周期管理；HTTP 层只负责路由与安全信封，浏览器层只负责面板与交互。扩展时应优先遵循“Wire-first、门面动词、窄接口镜像”的原则，避免在服务层、HTTP 层、UI 层各自维护一份形状或行为。
