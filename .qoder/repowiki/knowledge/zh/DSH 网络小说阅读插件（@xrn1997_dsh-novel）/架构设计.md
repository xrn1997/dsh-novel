单包双产物构建：`tsdown.config.ts` 同时产出 Node ESM 宿主半（`src/index.ts` → `lib/index.js`）与浏览器 CJS 客户端工厂（`src/client/index.tsx` → `lib/client.js`），后者通过官方三段式 banner/intro/footer 包装成 `window.__ModuleLoader__.load` 闭合工厂；类型声明由 `tsc -p tsconfig.build.json` 单独输出到 `lib/types/`。

- 依赖边界：peerDependencies 锁定 `@deepseek-ai/cordis`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/schemastery`、React，运行时注入的 platform modules（react、cordis、dsh-client-store/ui-slots/ui-primitives）在 `tsdown` 中以 `neverBundle` 列表保留为 require，不内联。
- 兼容性策略：`package.json.dsh.compatibility.dshReleases` 记录实际跑过的 DSH rc 版本；`vitest.compat.config.ts` 驱动兼容回放测试。
- 测试分层：`vitest.config.ts` 排除 compat/packaging-build 用例，`vitest.pack.config.ts` 先 build 再测打包产物，`tests/setup.ts` 统一装配，UI primitives 通过 alias 指向 `tests/client/ui-primitives-stub.tsx`。
- 发布契约：`files` 仅包含 lib/locale/icon.svg/cordis.patch.yml/README.md/LICENSE，`exports` 暴露 `.`、`./client`、`./locale/*.json`、`./icon`、`./package.json`，安装入口由 `dsh plugin add @xrn1997/dsh-novel` 拉取 npm 预构建产物。
