仓库根不承载业务代码，仅通过以下配置文件定义插件的构建、发布与测试边界：
- `package.json` 声明 `@xrn1997/dsh-novel` 包，`main`/`types` 指向 `lib/index.js`，并通过 `dsh.bundle.patch` 注入 `cordis.patch.yml` 以把自身注册到宿主；`dsh.client.inject` 指定 web 平台并注入 `@deepseek-ai/dsh-client-ui-primitives`。
- `tsdown.config.ts` 产出两个目标：Node ESM 半（`src/index.ts` → `lib/index.js`，peerDeps 留 import、npm 依赖 inline）和浏览器 CJS 半（`src/client/index.tsx` → `lib/client.js`，三段式 banner/intro/footer 闭合工厂），并用自定义 plugin `dsh-novel-bundle-purity` 在解析阶段拒绝 Node builtin 与不在平台模块表的 `@deepseek-ai/*` 进入 client bundle。
- `vitest.config.ts` / `vitest.compat.config.ts` / `vitest.pack.config.ts` 三套配置分别覆盖常规单元测试、compat 回放集（`tests/compat/**`）与构建产物自检（`tests/packaging-build.test.ts`），共享 `tests/setup.ts`。
- `pnpm-workspace.yaml` 放行 esbuild 构建并排除 `@deepseek-ai/dsh-*` 的发布冷却闸。
- `AGENTS.md` 作为 Agent 工作须知，集中约定 wire 单点、纯度门、兼容性判据与文档纪律；`CONTEXT.md` 是领域词汇表入口；`cordis.patch.yml` 只含一条 id/name 注册项。
