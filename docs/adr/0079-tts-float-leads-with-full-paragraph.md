# 听书浮窗展开态整段可读，控件升到 32/44，收起态退成身份条

Status: accepted

浮窗展开态的第一职责是「这一句念到哪」，两行截断装不下一个自然段：正文区改吃剩余高度、装不下才在尾行挂「看全文」；运输行五件控件升到 32/44；收起态不再显示半截句子，只留播放环、身份、段号与一条章内进度细线。

## 背景

旧版（`ADR-0074`）把当前句立为主位，但形态尺寸被两个常量钉死：展开边栏 280×140 里，正文只拿到 36px（13px 两行 ≈ 40 字），剩下 104px 给了头行、八颗 24×24 控件与进度条；收起胶囊 168×56 里，句子只剩约 110px 宽的两行（≈ 18 字）。真实自然段常见 100–300 字——「看不全」是算术结果，不是字号口味。

同一份高度上还叠着三条结构问题：头行最左的 grip 点阵把手与「整行本来就能拖」重复；收起那颗 24px 钮挤在右上角紧挨齿轮，两颗最容易误触的钮并排；胶囊整块（含播放环）都接 pointerdown，位移过 3px 就吞掉点击，「点哪都能拖」是旧结构写出来的手感。

## 决定

1. **展开态四行骨架**：顶行 = 身份钮（点收起 / 拖移动）+ 齿轮两颗兄弟按钮，不嵌套；正文区吃剩余高度，13px / 20px 行高、`overflow: hidden`，截断时尾行右下角挂「看全文」，点了走已有的 `backToReader`（记重定位现场 + 切路由）；运输行 = 回阅读器 / 上一段 / 播放 / 下一段 / 停止，颗颗 ≥32、环 44；底行 = 语速 / 段号 / 章内进度条 / 定时倒计时，纯读数。理由：把高度还给正文，同时靠删 grip、读数降级、收起并入身份行腾出命中尺寸。
2. **正文区可拖不可点**：拖动 = 移动，点击无动作（避免误收起）；「看全文」、进度条、齿轮、环都是真控件，从它们起手不拖也不 resize。理由：拖面只留「身份钮 + 正文区」两处，控件区不再起手拖动。
3. **位移阈值 8px**：3px 会把「按一下播放环」判成拖走；8px 是手抖与真拖的分界。拖动后补发的 click 由根节点捕获层统一吞掉（胶囊与边栏共用一份）。
4. **收起态退成身份条**：播放环（包播放 / 暂停钮，仍是真控件）+ 书名 + 段号徽标 + 底部一条章内进度细线；句子只在展开态出现，一出现就是完整的。理由：18 字不是读数，是噪音。
5. **空章不塌骨架**：正文区居中显示「本章没有可朗读的段落」，进度条不渲染；底行在没有其它读数时整行不渲染，把高度还给正文区。

## 边界

- 浮窗仍不是阅读器：不滚动、不翻页、不做选词；读全文回阅读器。
- 封面仍归书架与详情页；浮窗不新增封面 URL 依赖。
- 浮窗只有一条章内进度：收起态的细线与展开态的进度条同算式、同 value，仍是段粒度；段内时间读数不进界面（`ADR-0075`）。
- 两个完整形态、不做半隐与 hover 抽屉（`ADR-0073`）。
- 尺寸可调的裁决住 `ADR-0080`；本篇只管内容层级与命中档。

## 被否方案

- **逐句跟读**（只显示正在念的那一句）：句子天生短、一定看得全，但「句」是本仓不存在的粒度，且浏览器直出型音频没有时长读数，拿不到段内比例就定位不到当前句——同一个浮窗会为两种引擎长两张脸。
- **只留一行 + 一键回阅读器**：遮挡最省、零新概念，但没有回答「在浮窗里一次看全当前段」这条诉求，只是把责任推给一次点击。
- **保留两行截断、只调字号或补第三行**：还是在 36px 的坑位里做文章，控件命中尺寸也没有余地；不删 grip、不合并读数，运输行依旧贴边。
