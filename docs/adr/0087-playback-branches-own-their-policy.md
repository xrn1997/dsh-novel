# 出声分支的策略归分支实现，静音另一条的时序是「新分支出声那一刻」

Status: accepted

播放层两条出声分支（直出 / 字节）各自的准备、能力、静音与重来许可此前散在状态机的多个方法里，换参数那一刻就撤旧声音、切到字节引擎要先吃一段死腔。决定把这些策略收进出声分支的实现，并把「静音另一条」的时机定在新分支**出声那一刻**（合成等待里旧声音继续、起播失败当场收口）——加第三条声道只加一个分支实现，状态机一行不动。

## 背景

状态机按模式分叉的判据散在多个方法里（按模式查分支、预取、音色闸都有分支判断），每条分支「准备一段是什么、能提供什么、重来要什么许可」都埋在调用序列中间，「哪些步骤是分支差异」只活在注释里。行为侧，「参数 / 引擎变更必须把旧声音撤掉重开」的旧口径把静音绑在换参数那一刻：从直出切到字节引擎，合成在途的整个窗口耳朵是空的，回执落地才听新声；而字节 ↔ 字节的重取从来是「旧音频换槽接替、载入期间继续放」。两套时机并存，失败径上「读数写不在放、旧声音还在念」还没有主人。

## 决定

1. **分支策略住分支实现**（`PlaybackBranch`）：准备这一段（字节型求合成回执、直出型过平台音色）、能力声明（段内计时 / 预取 / 回执续播 / 介质自愈 / 音色表来源）、起播资格（`ready`：直出型等平台语音表，字节型无源级闸）、生命周期（`yieldForLoad` / `pause` / `stop` / `release`）都由分支自己回答；状态机只消费结局（started / cancelled / failed），不按模式分叉。
2. **「静音另一条」由各分支起播时自己做，时机 = 自己出声那一刻**：直出型起播是同步动作，先静音对侧再开口；字节型要等合成回执落地，先静音对侧再交介质。两条硬规则同时成立：**绝不叠音**（两句叠音比一句不响更难解释）、**能不出死腔就不出**（换槽接替：合成等待里旧声音继续到新声音就绪）。
3. **起播失败也要收口**：失败径先让两条介质闭嘴再记账——读数写「不在放」就不许还有声音（与暂停收口同一条判据）；**取消（cancelled）不碰对侧**——那一发已作废，声音归更新的那个动作管，晚到的作废回执不许掐掉新声音。
4. **组只管「两条都不该再响」的收口**：`pauseAll` / `stopAll` / `releaseAll` 落到两条介质，不认模式、不认业务字段；切引擎的窗口里旧介质可能还在响，收口必须两条一起。

## 边界

- 状态机仍住 `src/client/tts/listen-session.ts`：单元状态机、连败暂停、定时、位置落盘、两只 AbortController、回执缓存与取消管路（`ADR-0081` / `ADR-0082` 的锚点不搬）。
- 介质适配器仍是两个家（`src/client/tts/bytes-output.ts` / `src/client/tts/direct-output.ts`）：分支管策略，适配器管槽与平台接口，分支不直接碰音频元素与发声面。
- 分支不读 store、不写盘、不推进段号；上屏读数归 `src/client/tts/listen-readout.ts`。
- 章载入窗口的让位语义（`yieldForLoad`）不属本篇：章正文在途时旧声音让不让位是分支自己的策略（直出型当场撤队、字节型继续放），失败收口只管「起播失败」这一格。

## 被否方案

- **维持散在状态机的分支判断**：加第三条声道要改多处，「哪些步骤是分支差异」只活在注释里，漏一处不会报错、只会出怪声。
- **用 mode 枚举把差异留在状态机**：分支差异不是参数值而是策略——准备、能力、静音、重来各是一段逻辑，压成枚举会把「谁负责重建现场」这类知识藏回调用序列。
- **换参数那一刻就撤旧声音（立即静音）**：合成等待期变成死腔，切引擎、跳章的等待里耳朵是空的；且与字节 ↔ 字节既有的「换槽接替」不对称——同一句「旧声音什么时候停」在两条路径上两个答案。
- **只在成功径延迟静音、失败径不收口**：合成落空后旧声音替失败的段继续念，屏幕写「不在放」耳朵里还在响——读数撒谎，正是失败收口那条要关掉的窗口。

## 代价

分支层多一层间接（每条分支一组方法的接口面）。「静音时机」是时序契约，必须用测试钉住（回执在途对侧不静音、落地先静音再交介质、失败径两条都闭嘴），否则一次顺手的重构会把死腔或叠音放回来。失败收口让失败径多一次全组暂停，换来读数与耳朵一致。

锚点：契约 `src/client/tts/output-contract.ts` 的 `PlaybackBranch` / `ListenBranches` / `BranchHost`；实现 `src/client/tts/playback-branches.ts` 的 `BytesBranch` / `DirectBranch` / `createListenBranches`；失败收口 `src/client/tts/listen-session.ts` 的 `segmentFailed`；钉子 `tests/client/tts-playback-branch.test.ts`（能力声明、静音时序、cancelled 不碰对侧）与 `tests/client/tts-session.test.ts`（「失败收口：切引擎后合成落空……」「暂停收口两条介质」）；词汇 `CONTEXT.md` 的「直出型 / 字节型」；对照 `ADR-0081` / `ADR-0082`（回执缓存与取消管路留在会话）。
