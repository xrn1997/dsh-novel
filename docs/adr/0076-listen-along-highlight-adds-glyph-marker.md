# 跟读高亮在换字色之外补一枚段首小三角：纯换色的可辨度不够

Status: accepted

此前的跟读标记只换字色，但实测（纸色网格）显示纯字色差在白纸上只是「稍暗一点的棕」、深纸浅字上像「淡了一档」——对比度门量的是读得清，量不出认得出。决定：命中段保留换字色，另在段首框外画一枚 `currentColor` 小三角；仍不铺底色、不画进度线、不滚动。字形标记不靠色彩差说话，任何纸色下都一眼读得出「就是这一行」。

## 背景

用户反馈：深色纸主题下正在念的那一段「只是稍微更亮了一些」。复核 `paperLiveInk` 的取值链发现这不是 bug 而是判据缺口：算法的可量判据只有对比度下限、候选不反色与暖赭带里取色差最大的一档；但「更远」的方向随纸翻转，色差在部分纸色的角落还会更窄。对比度量「读得清」，色差量「两种颜色不同」——扫读定位要的「就是这一行」，两把尺子都量不到。

## 决定

- **换字色 + 段首一枚小三角**：`--novel-live-ink` 原样保留；新增 `.novel-tts-live::before` 实心三角，`border-left: solid currentColor` 跟着命中段的字色走，不引入第二个色源。三角浮在段框外沿，落进正文列内边距；正文段首两格没有内容起点，压不到字。
- **几何约束照旧**：命中块自身设 `position: relative`，伪元素绝对定位不进流；高亮进出不动布局、不触发滚动补偿、阅读位置不漂。浏览器几何门逐段比对开/关高亮的矩形。
- **注释面板不留半标记**：`.novel-notes` 里显式收掉这条 `::before`——同族浮层 `overflow: hidden` 会把出沿的三角裁成半截。

## 边界

- 不翻「只换字色」的另外两条：底色与段内进度线仍不做（底色把正文读成提示卡；段内没有逐字时间戳，画进度是假精度）。
- 不碰 `paperLiveInk` 的算法与下限；本篇只加第二条腿。
- 三角只做「哪一段」的二值标记，不做方向动画、不做段内位置。

## 被否方案

- 只调算法：白纸上往更深走会撞上「像引用」的另一头；色差要求再严也仍押在色彩差一条腿上。
- 恢复底色：病没变，不该因为另一条腿缺失就复活它。
- 左竖条：贯穿整段的重量，三角只点一下段首。
- 整段加粗 / 描边字：改字重会重排文本，破坏「高亮进出不动几何」。

## 代价

多一件要维护的呈现事实：三角的尺寸、锚定与「notes 场景收掉」都得有测试钉住。窄栏极限下三角可能压住首行缩进那一格——段首两格本无内容起点，观感代价接近零。
