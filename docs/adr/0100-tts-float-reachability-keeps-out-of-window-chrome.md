# 听书浮窗的可达区让开宿主窗控带，夹取与吸附以可达区为界

Status: accepted

`ADR-0073` 的自由落位把夹取域定成整个视口，边界还写明「不避让宿主 chrome」——这条被桌面版证伪：宿主窗控带（缩小 / 最大化 / 关闭栏，整条是窗口拖拽区）画在浮窗之上，浮窗进了那条带连拖面都摸不到，松手吸附还会主动把它送进去。决定：**浮窗的可达区 = 视口减宿主窗控带**，夹取、吸附、缺省落位、尺寸上限与弹层余量都以带下沿（安全顶）为顶界；位置规则的其余部分照旧。本篇取代 `ADR-0073`。

## 背景

被窗控带盖住在桌面版不是视觉遮挡而是可达性问题：那条带吃指针事件（窗口拖拽区 + 窗控钮），浮窗的拖面（胶囊身份钮 / 展开态正文区）被盖住后既抓不到、也挪不出来。两个动作把它送进去：拖动夹取只保证「整块在屏内」，顶边可到视口顶；松手吸附的「贴顶」还会把近顶的浮窗拉到贴视口顶。用户现场的形状：浮窗停到右上角就再也拖不出来。

## 决定

1. **可达区 = 视口减宿主窗控带**：纵轴夹取、松手吸附、缺省落位与展开态呈现高度都以窗控带下沿（安全顶）为顶界，浮窗任何形态的整块（含拖面）不得越进带里。可达性是硬约束，不是遮挡偏好。
2. **窗控带读数取可达性口径**：有 Windows 窗控栏且非全屏 = 栏高本身（安全顶就是带的下沿，不带视觉余量），全屏（栏不占位）与没有这条栏（纯浏览器）= 0——网页端零回归，浮窗照旧能贴顶。读数只住窗口读数那一处，进判据线前过 `clampTopInset`（`ADR-0089` 的那把尺）。
3. **吸附端点是可达区边**：「贴顶」= 贴安全顶；四边 gap 阈值与两轴独立不变。贴边形态（`data-flush`）只认真贴上的竖边，不变。
4. **贴着的边继续贴**：视口尺寸与窗控带读数（全屏切换）变化后，贴安全顶的块跟到新安全顶；自由位置只夹不漂；缺省轴不参与。
5. **设置弹层的上方余量从安全顶起算**：窗控带那条不进余量，弹层不许开进带里；上方优先、下方真更大才翻不变。
6. **卡死自愈**：落盘在带里的旧现场在挂载 / 换形态 / 视口变化的重夹里自动捞回可达区，不设专门的「解卡」动作。
7. **位置与形态的其余规则照旧**（本篇接管 `ADR-0073` 的全文）：现场记块中心（两轴各可为 null = 缺省）与展开态宽高意图；拖动两轴跟手、拖动中不吸附、松手才吸；`side` 是派生值；尺寸可量则量、量不到用常量、呈现夹取不回写（`ADR-0080`）；键盘四向移动（Shift 三档）、Home 回缺省位置；设置面与阅读器条共读同一份行清单；全局快捷键不抢阅读器。

## 边界

- 仍不避让状态泳道与正文：只保证整块在可达区内，落哪由用户定。
- macOS 红绿灯不做让位：本篇只管可达性，那一小块之外仍有可抓面积；真出现同款卡死，再按浮层夹取用的那条顶界口径扩。
- 不压宿主 z 序：窗控带必须赢，浮窗不去抢那条带的指针事件。
- 不做 hover 唤醒 / 半隐胶囊：触屏没有 hover，`ADR-0073` 已否。
- 两个完整形态、进度不撒谎、能力不丢不变；在场判据仍归 `ADR-0072`。
- **安全顶跟着窗口读数走，不另设监听**：带读数与视口尺寸在同一次窗口读数里取（`readViewport`，控制器构造、重连与 resize 各一次），所以本篇的自愈面 = 挂载 / 换形态 / 窗口读数变化三处。「窗口读数没动而那条带自己变了」不在本篇的自愈面里——全屏切换必然改窗口高，落得进这条口径。
- **验证半径止于本仓能起的那扇门**：单元 / 行为网把「带在场时的夹取、吸附、缺省落位、弹层余量与自愈」钉住，读数由用例自己种；那条带在桌面真机上是否真按这份读数出现，门量不到，要人工在桌面版复核一次。

## 被否方案

- 只做卡死后兜底（全局 Home / 双击复位）：能救场，不治「吸附主动把浮窗送进窗控带」的源头；兜底可另加，不作主修。
- 完全吃 `--dsh-frame-overlay-top`（含 macOS 红绿灯让位）：那是浮层的视觉摆放口径，本仓不保证它在纯浏览器里也零回归，且红绿灯让位超出可达性需要。
- 带下再留 20px 呼吸带：可达性不需要那 20px，视觉余量是浮层落位的口味，浮窗贴带下沿即可。
- 只让右上角窗控钮那一小块：窗控带整条是窗口拖拽区，带的其余部分同样抓不到；按整条带算才与实际遮挡一致。
- 只在落盘时校验位置、运行时不夹：全屏切换与窗口尺寸变化都会改安全顶，运行中的重夹必须同一把尺。
- 给窗控带读数单装一条 DOM 变更监听：它只在桌面壳上出现，出现 / 消失都伴随窗口尺寸变化，已被窗口读数那一处覆盖；单独一条观察器是给没有的需求加钩子。
