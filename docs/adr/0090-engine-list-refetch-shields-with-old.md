# 引擎清单重取用旧清单顶住、失败才清空：音色行的「闪」是清场换来的形态抖动

Status: accepted

听书设置里的音色行按订阅清单决定渲不渲染；清单**每次打开设置都重取**（订阅引擎可能在配置页被增删，组件常驻不重挂也不该拿旧清单糊弄），这是既有前提。本篇定的是重取期间的两半政策：**重取不清空**——旧清单顶住到新清单整块替换；**失败不留旧**——按「不知道音色」渲染，下次打开重试。先清空再取会让音色行先消失再出现、设置卡跟着长高长矮一行，就是用户看到的那下「闪」。

## 决定

- **重取期间旧清单继续参与渲染**：读数在途不动已上屏的清单；新清单回来后整体替换，中途没有空帧。行在与不在由清单决定，清空等于用布局抖动播报「正在刷新」。
- **失败那一轮清空，按「不知道音色」渲染**：与重取相反的方向是有意的不对称——被删掉的订阅留着旧清单，会把「选了也合成不出」的项继续摆在选择面上（静默假值）；清空只是少一行，且失败同时进瞬时错误层，「不知道」说得出口。
- **政策住读面，不住各表面**：两半都实现于 `client/tts/use-tts-sources.ts`，听书条与迷你条共读这一个 hook；取数失败经调用方注入的上报口进既有错误层，不自造第二个错误家。

## 被否方案

- **每次打开先清空（原形态）**：音色行消失再出现、设置卡长高长矮各一次——「闪」正是这份清场。
- **失败也保留旧清单**：对称是省事了，代价是幽灵引擎可继续被选中、到合成那一步才炸；静默假值比临时少一行重。
- **只取一次不再重取**：配置页增删订阅要重挂组件才可见，与常驻层的在场方式冲突。

锚点：`src/client/tts/use-tts-sources.ts`；调用面 `src/client/tts/TtsBar.tsx` / `src/client/tts/TtsMiniBar.tsx`；`tests/client/tts-mini.test.tsx`（「音色行不闪」案钉重取不清空与失败清空两半）；`tests/client/tts-bar.test.tsx`（「引擎清单每次打开设置都重取」案钉重取前提）；`ADR-0083`（未就绪的源不进清单是另一条判据，本篇只管重取期间的去留）。
