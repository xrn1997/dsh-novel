# 半径由主语声明、由出口符号数得着：整本拒收成一处，痕收成一张表

Status: accepted

`ADR-0061` 定了判据（失败半径等于判据的主语），本篇定它怎么携带：**半径在知道自己是谁的那一处声明，而不是在 catch 处判**；整本拒只有一个出口符号；痕只能按半径表的名字发。理由是同一件事当时在两处各说了一套——而这类分叉只有把通道收成一条才不会再来一次。

## 背景

按 `ADR-0061` 落地之后，复盘导入面发现规则的执行形状与规则本身对不上，四条：

- **半径带着，但没人读**。`Finding` 的 `scope` 与 `severity` 由各发出点各自手填，而服务侧唯一的消费处把它们折进一句给用户看的话，Node 半没有任何一处按这两个维度分派后果。后果实际由异常子类、集合成员、布尔字段、`null` 返回等不同机制决定。于是「表」只活在散文里，`scope` 成了每条痕都要交的税。
- **一份文档的坏，取决于哪一步被 `try` 包住**。同一份正文文档，解码与解析失败会换成文档级异常落空页，而 `documentTitle` / `scanXhtml` / `convertXhtml` 撞出的 DOM 预算失败抛的是书级基类——**一页太深就让整本书打不开**。而异常类自己写着「超节点/深度预算」属文档级：接口与实现互相打脸。
- **基类 `instanceof` 把已经收窄的失败一起吃掉**。资源级与文档级是书级的子类，所以想接住窄失败就只能对基类判 `instanceof`——正文层一处 `classifyHref` 因此把「这条引用解不开」的类抹成字符串，再按元素级落；而包层同一个解析口抛的同一个事实按书级拒收。反向也漏：`resources.ts` 接住了自己在同一函数里抛的子类，消息被前缀两遍。
- **名册数的是文本，不是位置**。整本拒的名册靠「源码里 `throw new 书级异常(` 之后最长的一段散文」当锚点：改一句措辞门就红（半径没变），而携带半径的两个窄类对它完全不可见，`localbooks.ts` 又整个在扫描目录之外。名册比它想钉住的判据还容易漂。

另有一处相邻的形状问题：落盘的是投影出来的整句中文（处数、例子与动作句焊在一起），读面只能原样复读——换宿主语言后痕仍是当年的语言。拆开之后，合并、处数前缀与例子列表可以由读面按当下口径重算；**动作句仍是导入时写下的那句**（带着那一次的具体数值与原文，不能从码重造），换语言或改动作措辞仍只对重新导入的书生效。这条残余面写进注释，不假装已经解决。

## 决定

1. **半径在主语已知处声明**：一份被读的文档的预算（`XmlBudget`）自带 `subject`（包文档 / 正文文档 / SVG 资源），`xml.ts` 唯一的失败出口 `fail` 按它给类。于是解码、静态闸门、解析、深度与节点预算四条路对同一份文档给出**同一种**半径——不必在每个调用点外面再包一层 `try`，也不可能出现「这步包了那步没包」。包文档读不出仍整本拒，正文文档读不出就是那一页空白。
2. **整本拒只有一组具名出口**：`rejectBook`（抛出）与 `bookError`（构造，供 Promise 拒绝与异常包装那两处）。书级异常不在这两处之外被构造，这条由门检。名册因此能改成数**符号的调用点处数**（按文件），措辞随便改都不动门；半径要升格就得加名册，加名册要写 ADR——棘轮的方向不变，但锚点不再是一段话。
3. **「这条引用解不开」独立成一个类**（`EpubHrefError`），不是书级的子类：同一个解析口服务两种主语（包层一条声明、正文一条链接），共用一个类就必然要在一边 `instanceof` 基类。包层用 `packageHref` 收成书级（这条仍在 `ADR-0061` 的在册待裁里），正文层按自己的半径收成元素级，两边都不必再抹掉类型。
4. **痕只能按半径表的名字发**：`FindingLog.add` 收的是 `FINDING_RADII` 的键，半径与后果由表决定，调用点填不了也填不出 `book` + `fatal`（表里没这一格，所以「用痕绕开唯一拒绝通道」这件事从「靠正则不许」变成「发不出」）。这张表就是 `ADR-0061` 那张表的代码形状，规则第一次只住一处。
5. **低层交回事实清单，可变账本只住编排层**：包层、文档层、资源层各自内部记账、对外交回不可变清单，编排层按条并入（`addEntry`：处数照加、例子各留前三）。不按处数重放合并——重放会把并入那一本的例子折掉，而它本来一条都没丢。
6. **落盘的是拆开的事实清单，投影在读面现算**：`LocalEpubMeta` 存 `FindingEntry`（半径、码、资源、
   动作句、处数与例子），`GET /local/warnings` 按当下的 `warningListOf` 重算合并、处数前缀与例子列表；
   **动作句本身是导入时的原文**（含那一次的具体数值），改它的措辞或换语言不回写旧书。旧书元数据里
   没有这一项时原样用它存过的那份投影（读时兼容，不回写）；新书同时落一份 `warnings` 投影，只为
   旧版本读面在降级时仍能显示导入说明（读面仍以 `findings` 为准）。这一项只在「导入说明」里重看，从不参与
   读取、导出或工具判断，为它把整份元数据再写一遍不值。跨半契约不变——`scope` 与 `severity` 仍不上 wire。

## 边界

- 不改 `ADR-0061` 的判据：什么算书级、什么只影响一格，仍由那篇定；本篇只改「半径怎么带出门」与「名册怎么数」。
- DOM 预算失败归文档级是**执行那篇已有的规则**（那篇的边界清单里没有这一族，而它写了可降级的失败只发生在读成功之后），不是新增豁免；一份文档读不读得出仍按 `hasVisibleContent` 判，空白冒充有正文依旧不许。
- 窄类的继承关系照 `ADR-0061` 的措辞保留（资源级与文档级仍是书级的子类），但**不许对基类做 `instanceof` 判半径**——这条由门数接住点：基类只许归档层那一处（它判的是「披过本层的名没有」，不是主语归谁）。
- 运行期读产物的损坏口径不变（`localbooks.ts` 的 `readDocument` 显式选 500 那条）。

## 后果

- 一页太深或太宽的真实文档不再让整本书打不开：它进阅读序列、占章号、目录有名，点开是空白页，痕点名这份文档与原因。钉住这一形状的两个样本各补了一章正常正文，好让「全空才整本失败」那条边界继续单独可测。
- 名册从「按报错文本登记的条目」收成「按文件登记的处数」；XML 层那一族文本锚点里属于正文文档的那几处，随半径降回它自己的主语而离开名册。
- 报错文案从此可以自由改写而不触发半径门；反过来，同一文件里净增一处整本拒一定触发（等量替换由评审兜底）。
- 用户可见的承诺面（哪些情况整本失败、哪些降级并看得见）随本篇同批改 `README.md`。
