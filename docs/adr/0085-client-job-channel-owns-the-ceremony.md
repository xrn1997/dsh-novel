# 浏览器半的任务观察通道共用一份仪式，三套收手语义显式成回调

Status: accepted

三个观察者（聚合搜索轮次、分类轮次、任务状态镜像）此前各写一份通道机械：timer 所有权、SSE 优先加快照轮询兜底、任一时刻只一条通道、撤通道连 timer 一起、代际作废在途帧。同形的是**仪式**，不是收手：搜索面握累积器、靠轮次身份换轮并从基线重读；发现面无累积器、整帧替换、只认通道代际；任务状态镜像无推送、无身份、只镜像。决定把仪式收进一个 module，三种策略作为回调显式交出——与 Node 半 `services/job-holder.ts` 的分界同一条：只统一仪式，不统一槽政策、快照形状与业务判据。

## 决定

- **通道拥有「什么时候问、问完怎么收」**：timer 的排与撤、订阅与轮询二选一、终态自关流、读失败后是否续拍、以及「身份不符 → 先撤通道 → 问恢复策略 → 按新轮重开」的编排。调用方交六件事：读面、订阅、应用、身份判据、恢复策略（可选）、读失败取舍。
- **身份判据与恢复策略内容留在调用方**：`sameRound` 恒真是调用点显式声明，不是通道缺省；`regain` 只有搜索面给，缺席即收手。
- **撤通道连 timer 一起撤销为唯一实现**：`clearTimeout` 只拦还没起飞的、`abort` 只断流不断回包，两者都撤不回已经飞出去的那次读——代际让它在落地时认出自己没有所有权。
- **快照轮询是地基、SSE 是加速器**：通知不 replay，可靠恢复必须有 baseline / cursor / 显式 query；订阅断开或提前结束而本轮未终态时回落轮询，终态后一条通道都不留。

## 被否方案

- 维持三份实现：两条不变量（任一时刻只一条通道、迟到帧不污染）由三份注释、三份测试各证一遍。
- 抽一层只做转发的壳：壳拥有编排而不是转发，身份判据在调用方，通道拥有两者之间的次序——这一段三份此前各写各的。
- 用 mode 枚举统一收手语义：不同收手不是一种参数的两个值，压成枚举会把「谁负责重建累积器」藏回通道里。

## 边界

- 不统一：快照形状、累积器与游标、整帧替换、身份判据与恢复策略的内容、节拍常量、错误文案与提示通道。
- 通道不认识 React，也不认识任何快照字段；挂载期生命周期归调用点。
- 任务提交仍归各调用点；通道只观察已经存在的那一轮。

## 代价

调用点从「三段自有实现」变成「六回调加一层间接」；差异全在策略内容，壳不必知道任何业务字段。回退面孤立：删掉某个调用点对通道接口没有影响。
