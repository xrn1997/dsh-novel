# 书城浏览轴从并集词表改成「先点名一个源、逛它自己的分类」

书城的浏览轴换掉：从「各源分类入口的精确同名并集」改成「先点名一个源、逛它自己的分类」。跨源视野从浏览面撤走，改由书籍详情浮层里一次**手动**聚合搜索承担。

并集词表不是没用的中间层，是读不了的一长串：本仓刻意不造同义词表（`docs/adr/0027` 立的口径——「玄幻」与「奇幻」是站点的真实分歧，替用户合并就是替用户猜），于是并集里绝大多数词条只挂一个源，左栏退化成没人读的清单，而「某一类到底是谁家的」得靠用户自己看计数反推。一个源的分类清单只有挂在这个源上才是答案，轴放错了。

被否决的做法：

- **并集 + 按源数阈值裁切**：阈值等于把某一次导入的形状焊成规则——与 `docs/adr/0027` 「不按被多少源声明设门槛」同一条口径。
- **并集 / 单源双档并存**：同一个面板里两套心智模型，用户要先判断自己在逛哪一种才能开始逛。
- **分组→源两级**：每次换源多点一下；而分组是书源包作者手写的、质不统一，撑不起一级浏览轴。
- **卡片直接进阅读**：简介、加入书架、跨源三个动作无处放，非阅读的动作全被挤进阅读器。

**代价**：

- 「同一本书在几个源上」不再是浏览面的一等信息——它变成一次要主动发起、会打到所有参与源、可以中途停止的搜索。
- 服务端搜索槽只有一个，在书城浮层里发起的这一次**会换掉搜索面持有的那一轮**。这是既有裁决「跟随最近一轮」（`docs/adr/0023`）的另一处落点，不是缺陷。
- 跨源归并器那一层整层随之下线——它是「跨源并集」那条轴的归并器，轴撤了它就没有消费方（撤的是唯一那份跨源合成书单的实现，浏览面从此一条命中就是一本书）。

本篇**不推翻 `docs/adr/0027`**：那篇讲的是发现面接哪几种形态（数据面口径），本篇讲的是接进来之后按什么轴逛（呈现面）。

锚点：`src/shared/wire.ts` 的 `ExploreSources`（跨半契约形状，本篇换的就是它）；`src/services/explore.ts` 的 `deriveExploreSources`（「哪个源自己声明了哪些分类」的唯一派生）；`src/services/participation.ts` 的 `exploreParticipates`（谁进城的那条判据）；`src/client/city-view-model.ts` 的 `sheetKeyword`（跨源那一次的关键词构造，唯一主人）；`src/client/views/CityView.tsx`（左栏两级的落点）；`src/client/views/CityBookSheet.tsx`（浏览器半的书籍详情浮层，本篇把跨源视野挪进来的落点——旧版那一层的职责是替用户点源，点源挪进左栏第一层之后它只剩一本书的落点，名字跟着职责换了）；矩阵行 `c-explore-url`、`d-explore-three-forms`。这一行只点名在盘上能回查的东西。
