# 搜索结果的默认轴从按源换成按书：归并只进呈现层，不碰身份

Status: accepted

聚合搜索的默认视野换轴：不再一家一段往下翻，而是**一本书一行**——同一本（规范化书名 + 规范化作者）在若干家源上的命中收成一行，行头报「N 家源」，「都加架」一次把这一本的各家**逐条**都进架（条数与家数可以不等，见下面「代价」那节），逐源行收进本行展开区。换轴买到的东西有读数（台架默认场景：默认要画的行从两万余降到个位数、把一本各源都加架从上百次点击降到两次；真机侧读数由 `DSH_SEARCH_FILTER_AUDIT` 的门补量）。

**归并口径**：键是 `(规范化书名, 规范化作者)`，规范化复用相关性那一份（`docs/adr/0032` 立的 `normalizeRelevance`，不写第二份）；**只有 `kept` 参与归并**——`suspect` 焊进同键就是成堆假书。序 = 相关性档 → **去重后的家数**降序 → 首个源到达序。第二子句数的是家不是行：一家撞两条同键写法的 sloppy 源若按行数计，会压过两家真答话的源——而「N 家源」那一栏承诺的就是**家**。`sources[]` 仍逐行保留：行与家是两条读数，绝不折叠；每行自带书名与作者、不归一不投票，「这一家把它叫作什么」在展开后照样看得见。书行那两个名字取首个到达源的原样。默认视图最多 `SEARCH_BOOKS_CAP` 本，超限那一行照实报「本轮共 N 本，只列前 M」且 `total` 报全量——只截视图不截账目；宽关键词下相关性判据几乎不滤（`kind` 命中即放行），上限是主力不是装饰。**逐源那一档不删、降级**为页尾折叠「按源看」，失败源折叠原样仍在、只是搬进了它**里面**（要看未响应的家得点两次：先开「按源看」，再开其中「N 家书源未响应」那一档）：`docs/adr/0025` 拦合并的那句代价（源好坏从界面上消失）由这一档承接——合并只负责浓缩，降级不删才保得住排查轴。单位律（条／本／家三条身份）的唯一住址是 `CONTEXT.md` 的「作品视图（按书）」词条，界面各处文案照它落字，本篇不复述定义。

**动作不下放**：书行只有「都加架」与展开两个钮，「读这本」只在展开后的逐源行里。本仓没有能判源好坏的读数（探针 `verified` 只证搜索面，不证正文），在书行放一个挑好源的「读这本」就是把猜测写进界面；展开即见各家原文与各自动作，选哪一家永远是用户的事。

**归并是呈现层投影，不是身份**：`MergedBook` 不落盘、不进 `SHELF_META`，书架身份是**地址单键** `bookKey`——`src/services/shelf.ts` 的 `Shelf` 按 `bookKey` 查找，`sourceId` 只是必填元数据字段，同一地址被两家加进架落的是同一个架位、`sourceId` 由后写覆盖，钉子用例「同 bookKey 再加：更新元数据，保留 addedAt 与进度」。「一本书挂多源」在架上是 N 个独立条目，原因是各家 URL 不同，不是身份带了源。「换源并保持进度」（作品级身份与进度搬运）明确**留待另裁**：那要一并裁章名对齐、缺章、付费章与 `bookKey` 是否升格，不是这次改造的量级；这次改造只留入口（展开某本 → 逐源「读这本」）。批量加架走浏览器半循环现有 `PUT shelf/:key`（服务端幂等），不新增写口、不动字段集。

**消费点两个，且刻意不是三个**：搜索结果页与工具面 `dshnovel_search` 吃同一份归并，不调第二个实现；书籍详情浮层**不吃**——那一层谈的本来就是一本，归并换不到任何浓缩，却会吞掉它那三条逐源读数（有命中／答了但零条／未响应），钉子显式钉着这条不下场。

**工具面的两条补账**：按书形状抹掉了「哪家没回」与源的探针状态（`status`/`statusDetail` 不再暴露），界面上有页尾折叠承接、工具面没有折叠——所以那里用披露三件套 `searched`/`answered`/`filtered`（跑了多少家、干净答话多少家、多少行因判不相关被移出默认返回）加 `failed` 逐家点名下账，「没人答话」与「答话了但全不相关」不许折成同一种结局。必然后果如实记两条：① 答了空页的源会被读成「答话」，模型要多调一次 `dshnovel_source` 才看得见原因；② 旧 `hits[]` 逐条带的 `coverUrl`/`intro`/`lastChapterName`/`kind`/`wordCount` 五项随换轴一起没了（`sources[]` 只留名字与地址）——`kind` 是判据用的三件字段之一（判据见 `docs/adr/0032`），模型判「这一行凭什么算相关」看不到它；简介与封面任何工具面都不再给，最新章/分类/字数要加架后从 `dshnovel_shelf` 的 list 读。

被否决的做法：

- **服务端持归并结果**：与 `added`/`next` 游标增量模型正面冲突——归并要整轮重排，重排装不进增量，等于把刚建好的读面模型废一半。归并留在调用方现算，键与序都是纯函数。
- **书行放「读这本」并替它选最优源**：没有能判源好坏的读数（见上），选源就是猜源。
- **URL 路径形似／简介相似当二级归并键**：自造判据——没人认得的相似度，反而提高焊错率；单键漏并已定意为可接受代价（见下），不用一个更没根据的量去补它。
- **现在就做作品级书架身份与进度搬运**：章名对齐、缺章、付费章、`bookKey` 升格四件事得一并裁，是另一篇 ADR 的量级，硬塞进这次改造只会逼呈现层替存储层做没裁的决定。

**代价**：假合并（两本不同作品撞同键）与漏并（同一作品被变体拆开）是这把键的固有代价，不是缺陷——它们只住呈现层，展开后每条命中的地址与动作都在原处，焊错一本的代价是**多看一行**，不是丢一条。多源批量加架会放大书架条目数（**一条一行**各发一发幂等 PUT——归并不去重行，一家可能给两条**不同地址**的写法，那一本就可能在架上落两个条目；同址的两行写法仍只落一个架位，加架回执按架位计）。宽关键词下上限成为主力，靠截断行照实报数兜住。

锚点：归并唯一实现 `src/shared/merge-by-book.ts` 的 `mergeBooks`；形状 `src/shared/wire.ts` 的 `MergedBook`／`MergedSource`／`SEARCH_BOOKS_CAP`；消费点 `src/client/views/SearchView.tsx` 的 `renderBooks`／`BookRow` 与 `src/tools/tools.ts` 的 `dshnovel_search`；浮层不吃归并的钉子 `tests/client/city-view.test.tsx`（用例「浮层的跨源那一列不折叠成一本」）；归并口径的钉子 `tests/shared/merge-by-book.test.ts`；对面那把键与各桶序的唯一读数口是矩阵行 `d-merge-dedup`（这次改造的读数以它为准，两处偏离也登记在那里）；相关性那层见 `docs/adr/0032`；本篇裁掉的是 `docs/adr/0025` 里「跨源搜索合并/归并：待裁」在**搜索面**的那一半；`docs/adr/0028` 撤的是发现面归并器，与本篇不冲突。
