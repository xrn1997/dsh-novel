# 搜索结果的默认轴从按源换成按书：归并只进呈现层，不碰身份

Status: accepted

聚合搜索默认视野换轴：**一本书一行**——同一本（规范化书名 + 规范化作者）在若干家源上的命中收成一行，行头报「N 家源」，「都加架」一次把这一本的各家逐条都进架，逐源行收进展开区。归并键复用相关性那份规范化；**只有 `kept` 参与归并**（`suspect` 焊进同键就是成堆假书）；序 = 相关性档 → **去重后的家数**降序 → 首个源到达序（数的是家不是行，`sources[]` 仍逐行保留，行与家绝不折叠）；默认最多 `SEARCH_BOOKS_CAP` 本，超限照实报「本轮共 N 本，只列前 M」。**逐源那一档不删、降级**为页尾折叠「按源看」，失败源折叠仍在它里面——`ADR-0025` 拦合并的那句代价由这一档承接。**动作不下放**：书行只有「都加架」与展开，「读这本」只在展开后的逐源行（本仓没有能判源好坏的读数，在书行挑好源就是把猜测写进界面）。**归并是呈现层投影，不是身份**：`MergedBook` 不落盘、不进 `SHELF_META`，架位凭 `bookKey`；「换源并保持进度」明确留待另裁（要一并裁章名对齐、缺章、付费章与 `bookKey` 是否升格）。**消费点两个且刻意不是三个**：搜索结果页与工具面 `dshnovel_search`；书籍详情浮层不吃归并（那一层谈的本来就是一本，会吞掉它三条逐源读数）。工具面用披露三件套 `searched`/`answered`/`filtered` 加 `failed` 逐家点名。必然后果如实记两条：① 答了空页的源会被读成「答话」，模型要多调一次 `dshnovel_source` 才看得见原因；② 按书形状下 `hits[]` 不再逐条带 `coverUrl`/`intro`/`lastChapterName`/`kind`/`wordCount`（`sources[]` 只留名字与地址）——`kind` 是判据三件字段之一（`ADR-0032`），模型判「这一行凭什么算相关」看不到它；简介与封面任何工具面都不再给，最新章/分类/字数要加架后从 `dshnovel_shelf` 的 list 读。被否决：服务端持归并结果（与游标增量模型冲突）；书行放「读这本」并替用户选源；URL 形似/简介相似当二级键；现在就做作品级书架身份与进度搬运。**代价**：假合并与漏并是这把键的固有代价，只住呈现层；多源批量加架会放大书架条目数。

锚点：`src/shared/merge-by-book.ts` 的 `mergeBooks`；`src/shared/wire.ts` 的 `MergedBook`／`MergedSource`／`SEARCH_BOOKS_CAP`；`src/client/views/SearchView.tsx` 的 `renderBooks`／`BookRow` 与 `src/tools/tools.ts` 的 `dshnovel_search`；`tests/client/city-view.test.tsx`（浮层不吃归并）；`tests/shared/merge-by-book.test.ts`；矩阵行 `d-merge-dedup`；`ADR-0032`；`ADR-0028`（发现面归并器，另案）。
