# 阅读与听书共用一条消费位置

Status: superseded by 0093

导语：阅读进度不再只是「阅读器读到哪」，而是阅读与听书共用的**消费位置**：播放层在同一个落盘节拍里写 `progress`（章 + 由段号换算的章内比例）与 `listen`（段号 + 播放参数），阅读器起播听书时跟随眼下看得见的位置。理由：用户对一本书只有一条「读到哪」的游标，听到第二章就该是读到第二章；两条互不相干的轨会让书架同时说两个位置，还能把正在听的人拽回更早的章。

## 背景

`ADR-0070` 把「播放位置回写阅读进度」（跟读）默认关掉了，听书位置与阅读进度各记各的。落地后，书架卡片要并列「读至」与「听至」两行，而读者的直觉是只有一个位置：听完第二章，阅读进度还停在第一章；读到第二章再按听书，旧的听书存档会把人拽回第一章。两条轨在「同一本书、同一个读者」这个前提下不是两个事实，而是同一事实的两份表示——阅读要章 + 连续比例（滚动恢复），听书要段号 + 播放参数（精确续听与按书记忆），两份表示都有用，但**位置的所有权只能有一个**。

## 决定

1. **`progress` 是唯一的消费位置**：`{chapterIndex, offsetRatio}` 由阅读会话与播放层共同写入。播放层在既有的位置落盘节拍（段间 2s 防抖、暂停、停止、关页 flush）里，把当前段按 `paragraphRatio(paragraphIndex, paragraphCount)` 换成章内比例，写 `progress`；同一节拍另写 `listen`。
2. **`listen` 降级为听书细节轨**：段号 + 引擎 / 音色 / 语速 / 音量。它服务听书自己的精确续听与按书记忆，不再参与书架卡片、最近阅读排序或开书恢复。
3. **起播跟随阅读**：阅读器顶条的「听书」pill 用实时阅读探针（章 + 可见段）作为起播点，量不到才退当前章首段；听书存档不决定起播位置，只提供播放参数与段级续听现场。`resume: 'archive'` 参数保留在播放层（显式调用时才从上次听到处续听），但当前**没有界面入口**：生产代码里 `startListening` 的唯一调用点恒传 `position`（阅读器 pill 与「从本段听」两个入口共用），界面不提供「从存档续听」按钮。
4. **同书边听边读的视口跟随归 `ADR-0091`**：跟随开启时阅读器随播放推进把视口带到当前段；读者手动滚动 / 目录 / 内链导航即让位，定位按钮重新接上。位置的写入仍以**最后一次显式动作**为准——让位后阅读器的滚动提交是用户动作；未让位时播放推进是后一次动作。共享的是落盘位置，不强制同步视口。
5. **「回阅读器」仍只站定不写**：一次性重定位把阅读器放到听书段，恢复路径（cause `restore`）不写 `progress`——一次定位不是一次阅读动作。
6. **书架只显示一条进度**：卡片按 `progress` 显示进度行，「正在听」徽标仍只标播放层此刻在放的那一本；「听至」第二行退场。

## 边界

- `shelfSaveListen` 服务端写口仍只写 `listen`；客户端在同一个落盘节拍里发两笔（`listen` 与 `progress`），各走各的值域门。两笔不是事务：一笔失败不拖住另一笔，下一笔位置各自再试。
- 阅读器视图与听书段仍可能短暂不同步（读者让位后跟随停止）；共享的是**落盘位置**，不是强制同步的视口。跟随开启时播放推进带视口走，让位后以阅读位置为准。
- 听书写入 `progress` 后，听过的书会被「在读」筛选命中、会按最近阅读排序前移——这是共享位置的预期后果，不是元数据变化。

## 代价

- 段号 → 章内比例是两端对齐换算，有损：听书写下的是段粒度位置，阅读器按比例恢复后由自己的锚点定位，可能落在该段附近而不是段首。反过来，阅读位置换算成听书段也只能落在最近的段。
- 每次位置落盘从一笔 PUT 变成两笔；失败半径各自独立，但会有一个极短的两轨不一致窗口（下一笔落盘收敛）。
- 书架少了「听至 第N章 · M段」的细节读数；精确段号只在听书条 / 迷你条里看。

## 被否方案

- **维持两条轨，只保留手动桥**（`ADR-0070` 原样）：书架同时说两个位置，读到第二章再按听书会被旧存档拽回第一章；这正是要修的那件事。
- **只存一份表示**（只存段号，或只存章内比例）：只存段号会让阅读器失去连续滚动恢复，只存比例会让听书失去段级续听；两份表示都保留、只让位置有一个主人，是代价最小的折中。
- **双向连续同步**（阅读滚动让音频跳段，听书推进让视口滚动且用户无法让位）：两个高频写者互相拽，用户会在自己滚动的瞬间被音频打断。`ADR-0091` 只接受「播放 → 视口」且带手动让位，不接受双向同步。
- **合成一个混合 body 原子写两轨**：要为 `PUT shelf/:key` 增加第五种形态、两套值域门合流，换来的只是省一笔本地 HTTP；现有两个动词各自的形状与校验更简单。

## 承接

`ADR-0070` 的位置轨那一条被本篇取代，但它关于听书范围的其余条款继续成立：四类引擎源（内置 / 浏览器直出 / 宿主语音服务 / legado HttpTTS 订阅）、订阅作为对象数据落 `tts-engines.json`、播放能力清单（预取、暖缓存、按书记忆参数、暂停 / 跳段 / 跳章、定时、跨界面迷你条）、模板 `speakVoice` 绑定、不做按角色分音色、不做宿主后台任务、不做交互式登录、不做清缓存入口。这些条款的 why 仍回查 `ADR-0070`；跟读高亮另一条由 `ADR-0076` 落地。
