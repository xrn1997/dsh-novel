# 认不出的规则语法在解析期抛错，不用空结果冒充失败

legado 书源规则是社区手写物，什么形态都有。我们决定：**白名单之外、又构不成选择器语法的段，一律在 `parseRule` 阶段抛 `UnsupportedRuleError`，带「面 + 段序 + 段原文」**，不用空结果冒充失败，也不留给求值期兜底。理由不是洁癖：判「哪些语法没被认出来」的两条读数口（解析面普查 `DSH_PARSE_CENSUS` 与导入预检）都按**真入口**跑全库规则串——把未知语法透传到求值期，普查会整族漏掉，错误阶段与错误类也全错，归因读数直接失真。空结果冒充失败是本仓定的最高罪。

被否决的方案：① 裸词透传到求值期再炸（同上，登记在册）；② 静默跳过或宽容猜测；③ 把「认不出」外扩到一切未知串——`词.词`、非 ASCII 标签名、含选择器特征字符者在对面的读法里**就是 CSS 选择器**，属「认得但没找到」那一侧，解析期定性成 `css` 段、零命中即 Miss；仍抛的只剩构不成选择器语法的形态。

**刻意偏离对面的一处**：同一条链混用 `||` / `&&` / `%%` 时对面允许（生效者由实现细节决定），本仓判为语义冲突、解析期拒。兼容目标是「书源格式写得出的规则本仓也读得出」，而不是把两种合并语义压成一个生效者。

锚点：`src/engine/parse.ts` 的 `KNOWN_MODES` / `isImplicitCss` / `isCssWordChain`；`tests/engine/parse.test.ts`；矩阵行 `a-unknown-segment-throws`、`a-css-implicit`、`a-combining-mixed`。
