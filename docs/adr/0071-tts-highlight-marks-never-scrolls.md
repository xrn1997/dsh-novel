# 跟读高亮只标记不滚动，定位是一次显式动作

Status: superseded by 0091

听书播放时在正文里标记正在被念的那一段（换字色 + 段首小三角，呈现形态见 `ADR-0076`），但**不自动滚动跟随**；要把视野带到正在念的段，由听书条上「定位到正在念的段」这颗显式按钮完成。自动跟随滚动会经阅读会话的滚动防抖把视口位置写成共用进度，与播放层自己的落盘节拍互相覆盖（位置模型见 `ADR-0078`）。

## 背景

阅读与听书现在共用一条消费位置（`ADR-0078`），但「听书时正文不动」与「听书时看不见念到哪」是两件事：前者是**不制造第二个写者**的要求，后者只是实现取舍。高亮本身不写任何状态——它只是播放层段号在正文块上的投影；真正会打架的是**滚动**：阅读会话把任何滚动（含程序写入的 `scrollTop`）经防抖落成 `progress`，自动跟随等于让视口在听书推进时不断改写位置，与播放层的落盘节拍互相覆盖。

## 决定

- **高亮只标记**：命中块换字色 + 段首小三角（纸墨派生，正文层不接宿主 token；形态归 `ADR-0076`），只动颜色与框外伪元素、不动盒模型——高亮进出不动几何，就不触发滚动补偿、阅读位置不漂。
- **定位是显式动作**：「定位到正在念的段」按了才滚，只滚阅读滚动容器自己（`centerInScroller`）；它与点目录同性质——用户主动导航落进度是它自己的语义，不是播放层在写。目标章还不在已载窗口时（听书跑得比阅读器快是常态），先走一次显式跳章（`requestJump`）把那一章载进来，章到货后再居中正在念的段；按钮不会因为目标章未载而按了没反应。
- **命中判据只有一份**：段号 → 正文块归 `paragraphSlotOf`（取最后一个 ≤ 段号的起段号），高亮与定位的 DOM 查找共用；文字章与图文章都按共享行清单的起段号折算。

## 边界

- 不做自动跟随滚动，也不做「高亮随播放平滑滚动」的开关：开关一旦存在，默认关也等于把越轨路径留给用户误开。
- 高亮不写 `listen` 也不写 `progress`：它是纯投影，播放层的位置落盘仍只走段粒度那一笔。

## 被否方案

- **自动滚动跟随播放**：阅读会话的滚动防抖不区分滚动的来源，程序滚动与用户滚动同一条落盘径；跟随即跟读回写，翻 `ADR-0078` 的案（阅读器不自动跟随音频）。
- **高亮时顺手写阅读进度**：位置写入已经归播放层的落盘节拍（`ADR-0078`），高亮再写一遍就是同一事实的第二个写者；自动跟随滚动还会让阅读会话与播放层互相覆盖。
- **按句高亮（字节型也切句）**：字节型音频没有句级时间戳，按字数比例切句是假精度；段是合成与落盘的真实粒度，高亮粒度与它对齐才不撒谎。
