# 听书播放层随插件卸载收口：常驻跨面板，不跨插件

Status: accepted

`ADR-0072` 把听书会话放进模块级常驻播放层，让阅读器子树卸载（切面板 / 关阅读器）时声音不断。插件**自身**被卸载是另一条边界：宿主拆掉客户端 fiber、撤走槽位注册，再把模块图重新 import 成一份新的——旧模块里的播放单例与它正在放的 Audio 不会跟着消失。那一路声音没有控制面，也没人暂停得了，还会继续合成、继续推进；宿主侧再点一次听书，新模块起播，两路叠在一起。故插件生命周期终点必须把播放层一并收口。

## 背景

客户端热替换与插件停用 / 升级都走同一条路：宿主销毁旧 fiber（`ctx.effect` 的清理逐个跑，`shell.overlay` 与 `main` 的槽位注册随之撤走），再把模块图重新 import 成新的一份。前一半是宿主插件生命周期的公开契约；模块图重建那一截本仓装不到宿主 UI 包、无法实测，按宿主发布物理解。模块级现场（播放会话、两只 Audio 槽、位置防抖）全部落在旧模块的闭包里；浏览器不会因为「模块没人 require 了」就停掉一个正在播放的 `Audio`。

症状分两步显形：控制面先整块消失（阅读器听书条与浮窗都随槽位注册撤走，场上没有任何播放控件），耳朵里却还在念；用户回到阅读器再点「听书」，新模块从共用的消费位置起播——旧的那路仍在念，于是两重奏。幽灵那一路还会一章章自动推进、按节拍写 `progress` 与 `listen`，把新会话的位置不断盖回去。

## 决定

- **插件卸载 = 播放层生命周期终点**：接线层（`src/client/index.tsx` 的 `apply`）注册一条 fiber 清理，调 `client/tts/player.ts` 的 `disposeTtsPlayer()` → `ListenSession.dispose()`。
- **收口动作是「先落位置，再停声，最后放介质」**：flush 位置防抖窗口里的最后一笔（用户听到哪就记到哪），复用 `stopListening` 的停声与代际作废，再 `releaseAll` 放掉两条分支的介质并摘掉 `pagehide` 挂钩。不得只把读数写成「不在放」——读数不是介质已停的证明。
- **在途起播一并作废**：起播取数 / 等语音表的 await 窗口里还没有活会话，`stopListening` 会早退、不抬代际；收口先自己抬一次会话代际，迟到的 `startSession` 回来只退场，不在卸载终点之后长出新会话——否则数据一到就照常起播，幽灵朗读换个时序复现。
- **视图卸载不调它**：面板切走、阅读器卸载、关书都不结束会话（`ADR-0072`）；这条清理只归 fiber 生命周期，不挂在任何组件树上。
- **不跨热替换交接会话**：新模块从共用消费位置与按书 `listen` 参数重新起播，不把旧会话搬过去。跨 reload 的状态搬运需要一条模块生命周期之外的持有者，等于给播放层造第二个家。

## 边界

- 仍不做宿主后台任务：宿主进程结束、页面关闭时播放随浏览器一起结束，与 `ADR-0072` 一致。
- 收口只作用于本插件自己的播放层；宿主里其它播放面（别的插件、平台语音）不在本仓判据内。
- 位置落盘仍是尽力而为：卸载瞬间那次写失败不阻断收口，也不改变下一次起播的恢复规则（共用消费位置 + 按书 `listen`）。
- 收口不区分「用户正在听」与「会话已暂停」：卸载是终点，介质一律放掉；暂停中的 Audio 槽因此也不留。

## 被否方案

- **让旧会话继续放，等用户自己发现**：控制面已经不存在，用户没有暂停手段；它还会继续合成、推进与落盘，下一次起播叠音——正是本篇要修的症状。
- **只在读数说「在放」时停声**：收口时必须干净，读数与介质现场可能不同步（切引擎窗口、失败收口的中间态）；拿读数当停声判据会把「屏幕说停、耳朵里还在念」留在生命周期终点。
- **把会话挂到 `window` 全局，热替换后重新接管**：跨模块搬运单例等于在插件生命周期之外再养一个不受 `ctx.effect` 约束的持有者，热替换后新旧两份状态的归属与清理都没有主人；收益只是省一次点击。
- **在 `pagehide` 里代替卸载收口**：`pagehide` 只在页面离开时来，客户端热替换时页面还在；两者不是同一件事，不能互相顶替。

锚点：`src/client/index.tsx` 的 `apply`（`dsh-novel: tts playback` 清理）；`src/client/tts/player.ts` 的 `disposeTtsPlayer`；`src/client/tts/listen-session.ts` 的 `ListenSession.dispose` / `stopListening` / `runSeq`；`src/client/tts/playback-branches.ts` 的 `releaseAll`；`src/client/tts/bytes-output.ts` 的 `release`；`src/client/tts/direct-output.ts` 的 `release`；`tests/client/tts-plugin-lifecycle.test.ts`、`tests/client/tts-session.test.ts`；`ADR-0072`、`ADR-0087`。
