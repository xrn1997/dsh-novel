# 兼容判据是书源规则怎么读，不是标准语义或库语义；偏离逐条登记

Status: accepted

判一条 legado 写法支不支持，依据是**规则的实际读法**（含畸形名与不标准的写法照收），不是 CSS/XPath 规范，也不是所引库的默认行为。基准由本仓自选，每条分叉的证据只登记在矩阵行，不拿外部实现的现状当权威。换成标准语义，读得出的就是规范而不是书源：`[attr~=正则]` 表达的是正则包含，按标准 CSS 的「词表包含」解会恒不命中——零命中冒充读法是本仓最高罪（分叉读数住矩阵行 `a-css-attr-regex` 的 `note`）；`HMacHex` 这种大写 H 的畸形名「顺手规范化」等于把输入里真实存在的 API 弄没；`java.ajax` 一族的失败路径若把错误文本回填正文，同为最高罪，本仓宁抛。

因此 CSS 类名与属性值维持大小写**敏感**（cheerio 语义），不做「宽松匹配」的放宽：放宽会让现有零命中形态变出多命中，`.0` 取位随之漂移。

偏离允许，但必须点名：只有无法承接或判为更坏处才偏离，且**偏离那一行要在覆盖矩阵里写明理由**——读数与理由的唯一家是矩阵行 `note`（登记纪律与分母的现量口径见 `ADR-0054`）。

被否决的方案：按标准语义解 `~=`；把畸形名改成规范大小写；把 ajax 失败当正文交给脚本；把类名/属性值改成不敏感匹配（重开条件：审计里出现第一条因大小写不一致而零命中的源）。

锚点：`src/engine/css.ts` 的 `JSOUP_ATTR_RE` 头注；`src/engine/js-utils.ts` 的 `jcaHashName`；矩阵行 `a-css-attr-regex`、`a-css-jsoup-text-pseudos`、`a-css-case-insensitive-match`、`h-digest-hmac-family`、`h-java-connect`。
