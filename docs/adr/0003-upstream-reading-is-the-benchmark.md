# 兼容判据是「对面怎么读」，不是标准语义或库语义；偏离逐条登记

判一条 legado 写法支不支持，依据是**参考实现的既有读法**（含畸形名与不标准的写法照收），不是 CSS/XPath 规范，也不是所引库的默认行为。换成标准语义，读得出的就是规范而不是书源。三条实证：`[attr~=正则]` 按标准 CSS 的「词表包含」解会**恒不命中**（目录 0 章）；`HMacHex` 这种大写 H 的畸形名「顺手规范化」等于把 API 弄没；`java.ajax` 失败时对面把异常堆栈字符串当 body 交给脚本，本仓宁抛——错误文本冒充正文是最高罪。

因此 CSS 类名与属性值维持大小写**敏感**（cheerio 语义），不做「宽松匹配」的放宽：放宽会让今天零命中的多命中与 `.0` 取位随之改变。

偏离允许，但必须点名：只有无法承接或判为更坏处才偏离，且**偏离那一行要在覆盖矩阵里写明理由**——读数与理由的唯一家是矩阵行 `note`（分母与登记纪律见 `docs/adr/0024`）。

被否决的方案：按标准语义解 `~=`；把畸形名改成规范大小写；把 ajax 失败当正文交给脚本；把类名/属性值改成不敏感匹配（重开条件：审计里出现第一条因大小写不一致而零命中的真实源）。

锚点：`src/engine/css.ts` 的 `JSOUP_ATTR_RE` 头注；`src/engine/js-utils.ts` 的 `jcaHashName`；矩阵行 `a-css-attr-regex`、`a-css-jsoup-text-pseudos`、`a-css-case-insensitive-match`、`h-digest-hmac-family`、`h-java-connect`。
