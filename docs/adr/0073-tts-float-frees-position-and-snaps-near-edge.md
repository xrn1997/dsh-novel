# 听书浮窗自由落位，松手时近边吸附

Status: superseded by 0100

听书浮窗的位置从「永远贴左右边缘」改成**自由落位**：现场记块中心坐标，拖动两轴跟手，松手时离视口边够近的那条边才贴齐，其余停在原地。两个完整形态、进度不撒谎与能力不丢是既有形态决定；形态与密度之后由 `ADR-0079` 改写、展开态尺寸由 `ADR-0080` 接管。本篇换掉的只是「自动贴边」这条位置规则。

## 背景

此前浮窗取「两个完整形态 + 自动贴边」，理由是贴边最省地方、也最不容易压住正文。代价是位置被规则吃掉：横向拖动被刻意忽略，松手一律按指针落在左/右半屏吸附回边缘，用户没有任何办法把浮窗停在正文中间或自己习惯的角落。这个功能叫「浮窗」，却只有一维自由度。

## 决定

- **现场记块中心**：`{ cx, cy, collapsed }`，两轴各自可为 `null` 表示用缺省。记中心不记左上角，换形态时视觉中心不跳，夹取与吸附都只需减半个尺寸。
- **拖动两轴跟手**：每一帧按指针位移落位并夹在视口内，拖动中不做任何吸附——吸附发生在松手那一刻。
- **松手近边吸附**：横轴取左右两侧 gap 较小者，近到阈值就贴齐那条边；纵轴同理且两轴独立，因此能落在边角。阈值住实现，不在本文抄读数。
- **`side` 降级为派生值**：不再作为现场字段，而是按 `cx` 与视口宽算出的呈现方向，只派生设置弹层往哪边开；贴边形态归 `data-flush`（`deriveMiniBarFlush`）管。视口变化时派生随宽度重算。
- **设置弹层纵向落位上方优先、下方真更大才翻**：两侧一样大留在上方；选定侧的可用余量与方向同批交出，弹层高度收到那一侧余量、卡内滚动。判据跟着现场重算。
- **贴着的边在视口变化后继续贴**；自由位置只夹不漂。
- **尺寸可量则量、量不到用常量**：量不到实际几何（无 DOM 宿主）时回常量，行为网仍可跑。
- **键盘四向移动**：方向键上下左右各移一档（Shift 三档），Home 回缺省位置；不再有「左右方向键换边」的独立动作。
- **设置面与阅读器条共读同一份行清单**：语速 / 音色 / 音量 / 定时 / 引擎 / 起播章只在 `TtsSettings.tsx` 维护一处。
- **全局快捷键不抢阅读器**：播放 / 跳段 / Esc 只在没有阅读器子树且浮窗真在场时安装。

## 边界

- 不做全宽底部坞（`shell.overlay` 推不动宿主布局，通栏形态会压宿主 chrome 与状态泳道）。
- 不做拖动中磁吸（实时吸附要在吸附瞬间重算拖拽基准，两轴阈值还会互相拉扯）。
- 不避让宿主 chrome 与状态泳道：只保证整块在屏内，落哪由用户定。
- 两个完整形态、进度不撒谎、能力不丢不变；在场判据仍归 `ADR-0072`。
- 不记自由左上角：现场是中心 + 收起态 + 展开态宽高。

## 被否方案

- 半隐胶囊 + hover 唤醒 / 同一胶囊端头抽屉：触屏没有 hover，收起态无法独立使用；把第二个形态伪装成第一个。
- 精修媒体卡：能力齐全但纵向堆叠过多，遮挡远大于控制需要。
- 竖签：换了控件形状，横胶囊的收起态能直接承接身份与读数。
- 拖动中磁吸：实现与测试成本高，用户感知不出比松手吸附更聪明的地方。
- 只放开横向的半自由补丁：位置语义同时有两个主人，迟早再打架。
- 保持贴边不动：位置被规则吃掉，正是要修的那件事。
