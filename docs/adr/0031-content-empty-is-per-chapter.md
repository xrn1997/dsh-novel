# 「空正文必炸」管的是首屏，不是跟进链上的每一页

Status: accepted

正文分档收窄：`chapterText` 里两处「这一页取不出正文」（规则取空 Miss、取到空文本）只在**首屏那一页**抛错并不写缓存；跟进链上的续页取空返回空表，由 `followPages` 的 zero-new 闸停止跟进，已经拼好的首屏照常交付。**为什么不是把 `ADR-0017` 推宽**：那条的理由是「空正文曾被当正常结果写进缓存」，危害单位是**一章**，判据就该落在章级产物上；把抛错放到每一页，等于让一条页级零命中拥有一章的否决权——最后一章的「下一章」链接指向书详情页（没有正文容器）时，前面各页明明有正文，整章却报「正文规则没取到内容」。**为什么不反过来判成站点侧问题**：能读出的判据是「这一章有没有正文」，不是「跟进链上有没有一页长得不对」。被否决：维持每页必抛；续页取空也追加空串继续往下跟（把「取不到」折叠成「取到空」）；在跟进层加「看起来不像正文页」的预检。**代价**：续页真的丢了时，产物是「少一页的章」而不是响亮报错；首屏那一半一字未放宽。

锚点：`src/services/online-reading.ts` 的 `chapterText`；`src/services/pagination.ts` 的 `followPages`；矩阵行 `g-content-empty-exception`、`g-chapter-boundary-guard`；`ADR-0017`（被本篇挪动了一个点的那条边界）。
