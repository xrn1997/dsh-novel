# 「空正文必炸」管的是首屏，不是跟进链上的每一页

正文分档收窄：`onlineChapterText` 里两处「这一页取不出正文」（规则取空 Miss、取到空文本）只在**首屏那一页**抛错并不写缓存；跟进链上的续页取空返回空表，由 `followPages` 的 zero-new 闸停止跟进，已经拼好的首屏照常交付。

**为什么这不是把 `docs/adr/0017` 那条边界推宽**：0017 立这条的理由是「空正文曾被当正常结果写进缓存（整章 0 字节，用户只见不出正文）」——那件事的危害单位是**一章**，判据也落在章级产物上。对面那侧同一条异常就落在章级：整章各页拼完之后才判「内容为空」，续页取空只是不追加、跟进自然收手（逐处对读与代码位置记在矩阵行 `g-content-empty-exception` 的 `note`，本篇不重复）。本仓此前把它放到**每一页**上，等于让一条页级零命中拥有一章的否决权：真机形状是某源最后一章的「下一章」链接指向书详情页（该页没有正文容器），前两页明明有正文，整章却报「正文规则没取到内容」。

**为什么不反过来判成站点侧问题**：站点把「下一章」写成书籍页在章尾是常态（没有下一章了，导航钮仍在）。能读出的判据是「这一章有没有正文」，不是「跟进链上有没有一页长得不对」。

被否决的做法：

- **维持每页必抛**：症状是整章不可读，而代价（防的是"空正文入缓存"）已经在首屏那一档完整付过了。
- **续页取空也追加空串、继续往下跟**：那才是把「取不到」折叠成「取到空」——本仓取值规约明令禁止的那件事，而且会让跟进穿过一串无正文页一直撞页数上限。
- **在跟进层加"看起来不像正文页"的预检**（比 URL 形态、比字节数）：那是替站猜；页级判定只有一个来源，就是正文规则自己取不取得到。

**代价**：续页真的丢了（站点分页里第 2 页恰好取不出）时，产物是「少一页的章」而不是响亮报错。这与 `docs/adr/0017` 里「逐章回退只服务个别条目缺链接」同族：个别页缺内容按缺内容处理，整章/整条链失效才炸。首屏那一半一字未放宽——空正文照旧抛、照旧不写缓存。

锚点：`src/services/reading.ts` 的 `onlineChapterText`（两处抛点与首屏档）、`src/services/pagination.ts` 的 `followPages`（zero-new 停跟进）；矩阵行 `g-content-empty-exception`（这条异常的家）、`g-chapter-boundary-guard`（同一条链上另一侧不许放松的闸）；`docs/adr/0017`（被本篇挪动了一个点的那条边界）。
